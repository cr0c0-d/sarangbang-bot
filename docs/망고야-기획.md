# `/망고야` — 봇에게 물어보기 기획안

대상: **망고** (`BOT_ROLE=mango`)
작성일: 2026-09-02
상태: **구현 완료 (2026-09-02).** 아래 결정대로 들어갔습니다.

| 정한 것 | 결정 |
|---|---|
| 답을 누가 보나 | **모두** — 같이 보는 재미 |
| 읽어주기(TTS) | **안 읽음** — 긴 답을 듣는 건 괴롭습니다 |
| 한도 | 사람당 1시간 **20번** / 서버당 하루 **150번** |
| 제공사 | **제미나이만.** OpenAI 는 붙이지 않습니다 |

⚠️ **제미나이만 붙였습니다.** 처음에는 "OpenAI·제미나이 둘 다, 관리자가 전환" 이었는데,
구독과 API 가 별개라는 것을 확인하는 과정에서 소유자가 제미나이 하나로 정했습니다.
그 덕에 어댑터 두 개와 전환 UI(관리자 권한 검사까지)가 통째로 사라졌습니다.

> ChatGPT Plus·Google AI Pro **구독은 API 와 무관합니다.** $20 를 내도 API 크레딧은
> 0 입니다. 제미나이를 고른 이유가 이것입니다 — **AI Studio 에 무료 등급이 있어서**
> 카드 등록 없이 시작할 수 있습니다 (분당·하루 횟수 제한 있음).

```
/망고야 질문:오사카 3박4일 가는데 우메다에서 저녁 뭐가 좋아?
  → 🥭 (답변)
```

## 1. 되는가 — 된다. 어려운 쪽은 AI 가 아니다

붙이는 일 자체는 작습니다. `fetch` 로 API 를 한 번 부르고 답을 디스코드에 쓰면 끝입니다.
**어려운 것은 그 주변**입니다 — 돈, 디스코드의 제약, 오류 안내.

| | 난이도 | 이유 |
|---|---|---|
| API 호출 | 쉬움 | `fetch` 한 번. `movie/tmdb.js` 와 같은 모양 |
| 디스코드에 답 쓰기 | 보통 | 3초 규칙, 2000자 제한 |
| **비용·남용 막기** | **여기가 진짜 일** | 친구들이 같이 쓰는데 요금은 소유자 카드로 나갑니다 |
| 오류 안내 | 보통 | 원인마다 다음 할 일이 다릅니다 (3.1-4) |

## 2. 제미나이만 붙인다 — 구독과 API 는 별개다

**소유자가 ChatGPT Plus 와 Google AI Pro 를 구독 중인데, 둘 다 API 와 무관합니다.**
이걸 확인한 것이 제공사 결정을 바꿨습니다.

| | 구독으로 되는 것 | 봇이 쓰는 것 |
|---|---|---|
| ChatGPT Plus | chatgpt.com 웹/앱 | platform.openai.com 에서 **따로 충전** (크레딧 0에서 시작) |
| Google AI Pro | gemini.google.com | aistudio.google.com 에서 **키 따로 발급** |

제미나이를 고른 이유는 하나입니다 — **AI Studio 에 무료 등급이 있습니다.**
카드 등록 없이 키만 받아 Flash 계열을 쓸 수 있습니다 (분당·하루 횟수 제한 있음).
OpenAI 는 무료 등급이 없어 반드시 충전해야 합니다.

- 모델 이름은 자주 바뀝니다. `GEMINI_MODEL` 로 빼뒀습니다.
  **무료로 쓰려면 Flash 계열** — 2026년 4월에 Pro 계열은 유료 전용이 됐습니다.
- 현재 한도는 https://aistudio.google.com/rate-limit 에서 봅니다.
  구글 공식 문서가 숫자를 안 적고 이 페이지를 가리킵니다. 자주 바뀌는 값입니다.
- ⚠️ **무료 등급은 보낸 내용이 구글의 서비스 개선에 쓰일 수 있습니다.**
  친구들 질문이 그리로 갑니다. 발급할 때 약관의 데이터 사용 조항을 확인하세요.

> ⚠️ 키는 **`.env` 에만** 둡니다. 로그에도 찍지 않습니다. `.env*` 는 이미 `.gitignore` 에 있습니다.

## 3. 비용과 남용 — **이 기획의 핵심**

봇은 개인 서버 2~3개에서 친구들이 같이 씁니다. 한도가 없으면 이런 일이 생깁니다.

- 누가 재미로 100번 물어본다
- 긴 글을 통째로 붙여넣는다 (**답보다 질문이 더 비쌉니다**)
- 답이 길어져 토큰을 계속 먹는다

**네 겹으로 막습니다. 전부 `.env` 값이고 기본값은 보수적으로 잡습니다.**

| 한도 | 무엇을 막나 |
|---|---|
| `AI_MAX_INPUT_CHARS` | 질문 길이. 벽지 같은 붙여넣기 차단 |
| `AI_MAX_OUTPUT_TOKENS` | 답 길이. 한 번의 최대 비용을 고정 |
| `AI_PER_USER_HOURLY` | 한 사람이 한 시간에 몇 번 |
| `AI_PER_GUILD_DAILY` | 서버 하나가 하루에 몇 번 |

### 숫자를 어떻게 정하나

소유자 서버는 6명이고 **자주 쓰는 사람이 5명**입니다 (2026-09-02 확인).

```
자주 쓰는 사람 수 × 1인당 하루 몇 번  =  서버당 하루 한도
        5명       ×      30번        =        150
```

⚠️ **위쪽 천장은 우리가 아니라 제미나이 무료 등급의 하루 요청 수(RPD)입니다.**
서버가 여러 개면 (서버 수 × 이 값) 이 그 천장을 넘지 않아야 합니다.
숫자는 자주 바뀌니 https://aistudio.google.com/rate-limit 에서 확인합니다.
넘겨도 큰일은 아닙니다 — 제미나이가 429 로 거절하고 봇이 그대로 알려줍니다.

⚠️ **분당 한도(RPM)는 우리가 막지 않습니다.** 5명이 동시에 물어보면 제미나이 쪽에서
걸릴 수 있는데, 그때 나오는 429 안내가 이미 "잠시 뒤 다시" 라고 말해줍니다.
같은 말을 하려고 한도를 하나 더 만들 값어치는 없습니다.

**실제로 조이는 것은 서버당 하루 한도입니다.** 사람당 한도는 "한 사람이 몰아 쓰는 것" 만
막습니다 — 사람당 10번이어도 서버 전체로는 하루 50번을 넘지 못합니다.
그래서 사람당 숫자는 넉넉히 둬도 안전합니다.

⚠️ **한도에 걸렸을 때 조용히 실패하지 않습니다.** 얼마나 남았는지, 언제 풀리는지 말해줍니다.

```
🥭 오늘 이 서버의 질문 한도(50번)를 다 썼습니다. 내일 0시에 다시 채워집니다.
🥭 30분에 5번까지만 됩니다. 12분 뒤에 다시 물어봐 주세요.
```

### 세는 값은 디스크에 남긴다

재시작하면 초기화되는 한도는 한도가 아닙니다. `data/ai-usage.json` 에 남깁니다.
**이미 있는 방식을 그대로 씁니다** — `music/history.js` 의 저장 + `flushHistory()` +
종료 시 flush, `poll/index.js` 의 복구. 새로 발명하지 않습니다.

> 여기가 "쉬워 보이는데 안 쉬운" 지점입니다. 공수의 절반이 여기 있습니다.

## 4. 디스코드 쪽 제약 — 미리 알고 시작해야 하는 것

### 4.1 3초 규칙 → `deferReply()` 필수

AI 응답은 2~20초입니다. 디스코드는 **3초 안에 응답**하지 않으면
"봇이 적시에 응답하지 않았어요" 를 띄웁니다. 일정 카테고리 고르기에서 실제로 겪었습니다.

```js
await interaction.deferReply();      // 먼저 자리를 잡고
const answer = await askAi(...);     // 그다음 오래 걸리는 일
await interaction.editReply(answer);
```

### 4.1-1 ⚠️ 디스코드는 **질문을 다른 사람에게 보여주지 않는다**

슬래시 명령어를 쓰면 채팅방에는 "○○님이 **망고야**를 사용함" 만 뜹니다.
**입력한 내용은 안 보입니다.** 그래서 답만 남으면 무엇을 물어본 건지 아무도 모릅니다.
소유자가 바로 이걸 지적했습니다.

→ 답 맨 앞에 질문을 **인용문으로** 붙입니다.

```
> 오사카 우메다에서 저녁 뭐가 좋아?

우메다면 스시로 어때? 회전초밥인데 가격 착하고 늦게까지 해.
```

⚠️ `>>>`(여러 줄 인용)을 쓰면 **뒤의 답까지 전부 인용**이 됩니다. 줄마다 `>` 를 붙입니다.
⚠️ 질문이 최대 1000자라 **첫 조각의 자리를 그만큼 빼야** 합니다. 안 그러면
   머리글 + 답이 2000자를 넘어 그 메시지가 아예 안 갑니다.

### 4.2 2000자 제한 → 잘라서 여러 번

디스코드 메시지는 2000자입니다. AI 는 그보다 긴 답을 잘 씁니다.

- 문단·문장 경계에서 자릅니다. 글자 수로만 자르면 단어가 잘립니다.
- **조각 수에도 상한**을 둡니다(예: 3개). 넘으면 "여기까지만 보여드립니다" 라고 적습니다.
  조용히 자르면 답이 이상하게 끝난 것처럼 보입니다 (재생목록 자르기와 같은 원칙 — 3.1-1).
- ⚠️ **그 안내를 붙일 자리를 미리 비워야 합니다.** 마지막 조각이 이미 2000자에 꽉 차 있으면
  붙이는 순간 2027자가 되고 **그 메시지는 전송되지 않습니다.** (verify 가 잡아낸 실제 버그)

### 4.3 ⚠️ 실시간으로 이어 쓰기(스트리밍)는 **v1 에서 하지 않는다**

AI 가 글자를 뱉는 대로 메시지를 고쳐 쓰면 멋있어 보입니다. 하지만:

- 디스코드 메시지 수정은 **5초에 5번** 제한입니다. 넘기면 조용히 밀립니다.
- 중간에 오류가 나면 **반쯤 쓰다 만 메시지**가 남습니다. 오류 경로가 두 배로 복잡해집니다.
- 답이 3~10초 만에 오는데 얻는 게 크지 않습니다.

기다리는 티는 `deferReply()` 가 이미 "생각 중…" 으로 내줍니다. **그걸로 충분합니다.**

## 5. 대화를 이어갈 것인가 — **v1 은 안 한다 (결정)**

한 번 묻고 한 번 답하는 것만 합니다. 빠뜨린 게 아니라 **정한 것**입니다.

- 대화를 기억하면 **매번 앞의 대화를 통째로 다시 보냅니다.** 길어질수록 비쌉니다.
- 누구의 대화인지, 언제 잊을지, 채널마다인지 사람마다인지 — 정할 게 줄줄이 딸려옵니다.

나중에 필요해지면 **디스코드의 답장(reply) 사슬**을 쓰는 게 가장 싼 방법입니다.
망고의 답에 답장하면 그 한 번만 앞뒤를 이어붙이는 식입니다. 지금은 넣지 않습니다.

## 7. 오류 안내 — 원인마다 다음 할 일이 다르다 (3.1-4)

| 제공사가 주는 것 | 망고가 할 말 |
|---|---|
| 키가 없음 | `.env` 에 `GEMINI_API_KEY` 를 넣고 재시작해주세요 (발급 주소까지 적어줍니다) |
| 키가 틀림 | 키가 거부됐습니다. 새로 발급받아 교체해주세요 |
| 429 한도 초과 | **무료 등급은 분당·하루 제한이 있습니다.** 잠시 뒤 다시 / rate-limit 페이지 확인 |
| 404 모델 없음 | `GEMINI_MODEL` 을 바꿔주세요 (무료면 Flash 계열) |
| 답이 비어서 옴 | 안전 필터 / 길이 초과를 구분해 안내합니다 |
| 제공사 쪽 혼잡 | 잠시 뒤 다시 시도해주세요 |
| 시간 초과 | (AbortController. `movie/tmdb.js` 와 같은 모양) |
| **모르는 오류** | **제공사가 한 말을 그대로 보여줍니다** |

마지막 줄이 핵심입니다. 오늘 하루 종일 이 규칙이 왜 있는지를 겪었습니다 —
추측한 원인을 적으면 그 뒤로 아무도 진짜 원인을 못 찾습니다.

사용자에게 보여줄 오류는 `userError()` 로 만듭니다. 그래야 로그에 스택 없이 메시지만 남습니다.

## 8. 어디에 무엇을 두나

```
src/ai/gemini.js     제미나이 호출 + 오류 한국어화 + 제한시간   (~160줄)
src/ai/usage.js      한도 세기 + data/ai-usage.json            (~80줄)
src/ai/index.js      /망고야 명령어 + 답 다듬기·자르기          (~120줄)
```

기존 뼈대에 **그대로 얹힙니다. 새로 만들 구조가 없습니다.**

| 붙일 곳 | 하는 일 |
|---|---|
| `config.js` 의 `BOTS.mango.features` | `'ai'` 추가 |
| `settings.js` 의 `FEATURES` | `ai: { label: '망고야', emoji: '🥭', … }` → `/기능` 에 자동으로 나옴 |
| `commands.js` | `...tag('ai', aiCommands)` → 꺼짐 처리 자동 (3.7-1) |
| `.env.example` | 키와 한도 4개, 한국어 설명과 함께 |
| `verify.mjs` | 아래 검사들 |

**명령어 안에서 기능 on/off 를 검사하지 않습니다.** `tag()` 가 합니다.

### verify 에 넣을 것

- 명령어 이름이 한국어인가, 스키마가 조립되는가 (6x 화면 검사에 추가)
- 키가 없을 때 **뜻이 통하는 한국어**로 답하는가
- 자르기: 2000자 초과 입력이 2000자 이하 조각들로 나뉘는가, 조각 수 상한을 지키는가
- 한도: 시간당 N번을 넘기면 거절하는가, 시간이 지나면 다시 되는가 (가짜 시계로)
- 한도 기록이 **재시작을 견디는가** (`flush` 후 다시 읽기)

## 9. 공수

| 덩어리 | 크기 | 위험 |
|---|---|---|
| API 호출 + 오류 한국어화 | 작음 | 낮음 — `tmdb.js` 를 본떠 씁니다 |
| 명령어 + 답 자르기 | 작음 | 낮음 |
| **한도 + 디스크 저장** | **중간** | **여기가 시간을 먹습니다.** 재시작을 견뎌야 하고, 시계를 다뤄야 합니다 |
| 문서·verify | 작음 | 낮음 |

**전체로는 작은 기능입니다** — 영화 고르기보다 작고 일정보다 훨씬 작습니다.
다만 "AI 붙이기" 자체는 30분이고 **나머지가 대부분**이라는 점을 알고 시작해야 합니다.

한 번에 넣지 않고 단계로 갑니다 (CLAUDE.md 규칙).

1. `askAi()` + `/망고야` — 한도 없이, 소유자만 쓰는 상태로 확인
2. 답 자르기 + 오류 한국어화
3. 한도 + 디스크 저장
4. `/기능` 연동 · 문서 · verify

1. https://aistudio.google.com/apikey 접속 → 구글 계정으로 로그인
