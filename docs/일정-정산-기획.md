## 0. 지금 어떻게 쓰고 있나 (이 기획의 출발점)

봇을 만드는 게 아니라 **이미 하고 있는 일을 덜 귀찮게** 하는 것이 목표다.
소유자가 설명한 실제 흐름:

```
1. 「일정」 카테고리 아래에 [yymmdd-일정명] 형태의 **비공개 채널**을 만든다
2. 그 일정 참여자에게만 권한을 준다
3. 그 채널에 필요한 걸 미리 보내둔다 — 숙소 정보, 예약 정보 …
4. 일정이 끝나면 그때 찍은 사진을 올린다
5. 보통 **한 사람이 결제**하고, 끝난 뒤 [누구-얼마, 누구-얼마] 를 적어두면
   각자 송금한다
```

**여기서 봇이 대신할 값어치가 있는 것**

| 지금 불편한 것 | 봇이 할 일 |
|---|---|
| 시간·장소·할 일이 채팅에 섞여 흘러간다 | 한 장의 **판**에 모아 고정해둔다 |
| 장소를 정해도 지도를 따로 검색한다 | 장소에 **지도 버튼**을 달아준다 |
| 예약 정보 같은 중요한 메시지가 위로 밀린다 | **우클릭으로 등록**해 판에 링크로 모은다 |
| `[누구-얼마]` 를 적고 누가 보냈는지 세어야 한다 | **/정산** 이 목록과 송금 버튼을 만든다 |

**봇이 하지 않을 것**: 채팅·이미지 자동 감지. 중구난방으로 올리므로 자동으로 긁으면
쓰레기만 쌓인다. **필요한 것만 사람이 직접 등록한다.**

## 1. 확정된 결정 (소유자 답변)

| 항목 | 결정 |
|---|---|
| 명령어 | **`/일정` 하나.** 여행과 나누지 않는다 — 여행 빈도는 낮고 대부분 당일치기 약속이다 |
| 날짜 입력 | **직접 적는다.** "이번 주말" 같은 말 해석기는 만들지 않는다 |
| 날짜 조율 | **연동하지 않는다.** 투표든 채팅이든 사람이 정하고, 정해지면 **수기로 등록**한다 |
| 정산 | 일정 기능에 섞지 않고 **`/정산` 별도 명령어**로 |
| 자동 감지 | **하지 않는다** |

핵심 기능 우선순위(소유자 표현): **"시간과 장소와 할 일을 등록해놓는 것"** 이 1순위.
지도 링크와 참고자료 기록이 그다음.

## 2. 개체 설계 — 일정 하나 = 채널 하나

지금 워크플로가 이미 **채널 하나에 일정 하나**다. 그 구조를 그대로 쓴다.

- 일정에 ID 를 만들지 않는다. **채널 ID 가 곧 일정 ID** 다.
- "어느 일정?" 을 물어볼 필요가 없다. 그 채널에서 명령어를 쓰면 그 채널의 일정이다.
- 참여자를 따로 관리하지 않는다. **채널 권한이 이미 참여자 목록**이다.

`data/plans.json` — `{ [channelId]: 일정 }`

```js
{
  title: '오사카 여행',
  at: 1791036000000,        // 시작 시각 (ms). 날짜만 정했으면 시간은 00:00
  hasTime: true,            // 시간까지 정했는지 (아니면 "종일" 로 표시)
  place: '스타필드 하남',     // 지도 검색어 그대로
  todos: [{ text, doneBy }],// doneBy: 체크한 사람 ID 또는 null
  notes: ['체크인 15시부터'],
  refs: [{ label, url }],   // 우클릭으로 등록한 메시지 링크
  panelMessageId: '...',    // 판 메시지 (재시작 후에도 찾을 수 있게)
  remindAt: 1790949600000,  // 알림 예약 (없으면 null)
  createdBy: '...',
}
```

## 3. `/일정` — 판 하나로 끝낸다

인자 없이 실행한다. 이 채널에 일정이 **없으면 만들기 창**, **있으면 판을 맨 아래로** 다시 띄운다.
(음악 제어판·갤러리 버튼과 같은 규칙 — 3.6-1)

### 3.1 만들기 창 (모달, 칸 5개 = 한도)

| 칸 | 내용 |
|---|---|
| **제목** | 기본값을 **채널 이름에서 뽑아 채워둔다.** `[251003-오사카]` → `오사카` |
| **날짜·시간** | `2026-10-03 18:30` / `10/3 18:30` / `10/3` (시간 없으면 종일) |
| **장소** | 지도에 넣을 검색어나 주소. 비워도 됨 |
| **할 일** | 한 줄에 하나. 비워도 됨 |
| **메모** | 한 줄에 하나. 비워도 됨 |

채널 이름에서 제목을 뽑는 게 작지만 큰 편의다 — 이미 채널명에 적어둔 것을 또 타이핑하지 않는다.

### 3.2 판

```
📅 오사카 여행
🕘 10월 3일 (금) 오후 6:30 · <t:…:R>          ← "3일 후" 를 디스코드가 세어준다

📍 스타필드 하남
   [🗺️ 카카오맵]  [🧭 네이버지도]              ← 링크 버튼

✅ 할 일  2/4
   ✅ 숙소 예약        (지예)
   ✅ 항공권 결제      (민수)
   ⬜ 렌터카 예약
   ⬜ 환전

📝 메모
   · 체크인 15시부터
   · 주차 3시간 무료

📎 참고자료
   · [숙소 예약 확인서](메시지 링크)
   · [렌터카 견적](메시지 링크)

[✅ 숙소 예약] [✅ 항공권 결제] [⬜ 렌터카 예약] [⬜ 환전]   ← 눌러서 토글
[✏️ 고치기] [➕ 할 일] [📝 메모] [🔔 알림] [💰 정산]
```

**버튼 줄 배치** (디스코드는 한 메시지에 5줄까지)

| 줄 | 내용 |
|---|---|
| 1 | 지도 링크 (장소가 있을 때만) |
| 2~3 | 할 일 토글 — 한 줄에 5개, **최대 10개** |
| 4 | `✏️ 고치기` `➕ 할 일` `📝 메모` `🔔 알림` `💰 정산` |

할 일이 10개를 넘으면 버튼은 앞 10개만 달고 목록에는 전부 보여준다.
넘칠 때 조용히 자르지 않고 **"버튼은 앞 10개만" 이라고 적는다** (재생목록 자르기와 같은 원칙 — 3.1-1).

### 3.3 장소 → 지도 버튼 (실측)

좌표도 API 키도 필요 없다. **검색어만 넣으면 된다.** 2026-09-01 실측:

| 지도 | 주소 형식 | 확인 |
|---|---|---|
| 카카오맵 | `https://map.kakao.com/?q=<검색어>` | 200 |
| 네이버지도 | `https://map.naver.com/p/search/<검색어>` | 200 |

둘 다 디스코드 **링크 버튼**으로 쓸 수 있음을 확인했다(`ButtonStyle.Link`).
모바일에서는 앱으로 열린다. 길찾기는 지도 앱이 알아서 제공하므로 우리가 좌표를 구할 필요가 없다.

> 검색어를 그대로 넘기므로 `스타필드 하남` 처럼 **가게 이름**이든 `서울시 …` 처럼 **주소**든 된다.
> `encodeURIComponent` 를 반드시 통과시킨다.

### 3.4 참고자료는 **우클릭으로 등록**한다

"명령어로 필요한 부분만 직접 등록" 요구에 정확히 맞는 방법이 있다 —
**메시지 우클릭 → 앱 → 📌 일정에 등록** (`ContextMenuCommandBuilder`, type `Message`).
2026-09-01 에 조립 확인했다.

```
숙소 예약 확인서 메시지 우클릭 → 앱 → 📌 일정에 등록
   → 판의 "📎 참고자료" 에 그 메시지 링크가 추가된다
```

**왜 이 방식인가**

- 이미지를 다시 올리지 않는다. **원본 메시지가 그대로 출처**다.
- 슬래시 명령어 목록이 늘어나지 않는다 (우클릭 메뉴는 별도 목록이다).
- 사진이든 글이든 예약 캡처든 **무엇이든** 등록할 수 있다.

메모는 짧은 글이라 우클릭까지 갈 필요가 없다 → `📝 메모` 버튼 + 모달.

### 3.5 알림

`timer/index.js` 구조를 그대로 쓴다 — `data/*.json` 저장 + 켜질 때 되살리기 + 음성/채팅 알림.

`🔔 알림` 버튼 → **하루 전 저녁 8시** / **당일 아침 9시** / **1시간 전** 중에서 고른다.
(고정하지 않고 셋 중 하나를 고르게 한다 — 당일치기와 여행의 필요가 다르다)

⚠️ `setTimeout` 상한은 약 24.8일이다. 그보다 먼 일정은 **켜질 때마다 다시 계산**해서
가까워지면 예약한다. 타이머 모듈이 이미 상한을 두고 있으니 그 값을 확인해 맞춘다.

## 4. `/정산` — 별도 명령어

일정 기능에 섞지 않는다. 일정이 없는 채널에서도 쓸 수 있다.

### 4.1 만들기 창 (모달)

**모달에 사람 고르기 칸을 넣을 수 있다**(`UserSelectMenu` in modal). 2026-09-01 확인.
그래서 한 화면에서 끝난다.

| 칸 | 내용 |
|---|---|
| **내용** | `오사카 여행 숙소` (기본값: 이 채널의 일정 제목) |
| **금액** | 숫자 하나면 **총액을 균등분할**. 여러 줄이면 **순서대로 개별 금액** |
| **나눌 사람** | 사람 고르기 (여러 명) |

- **결제자는 명령어를 쓴 사람**이다. 따로 묻지 않는다 — 실제로 결제한 사람이 정산을 올린다.
- 결제자를 「나눌 사람」에 넣어도 되고 안 넣어도 된다. 넣으면 자기 몫으로 표시되고 송금 대상에서는 빠진다.

### 4.2 판

```
💰 오사카 여행 숙소
결제: @지예 · 총 120,000원 · 3명

   @민수    40,000원   ⬜ 송금 전
   @수현    40,000원   ✅ 보냈어요
   @지예    40,000원   (결제자)

받을 돈  40,000원 / 80,000원

[✅ 보냈어요]                                  ← 목록에 있는 사람만
```

- `✅ 보냈어요` 는 **본인 줄만** 토글한다. 남의 것은 못 건드린다.
- 목록에 없는 사람이 누르면 "이 정산에 포함되지 않았습니다" 라고 알려준다.
- 전원이 보내면 판이 **초록색 + 정산 완료**로 바뀐다.
- 결제자가 확인 버튼을 누르는 절차는 **두지 않는다.** 단계가 늘고, 실제로는 보냈다고 하면 끝난다.

`data/settlements.json` 에 저장해 **재시작을 견딘다** (투표와 같은 방식 — 3.6-7).

## 5. 안 하는 것

| 안 하는 것 | 왜 |
|---|---|
| 채팅·이미지 자동 감지 | 중구난방으로 올리므로 긁으면 쓰레기가 쌓인다 (소유자 명시) |
| 날짜 조율 투표 연동 | **과하다** (소유자 표현). 정해지면 수기 입력이 낫다 |
| 일정 / 여행 구분 | 여행 빈도가 낮다. 하나로 충분하다 |
| 월별 캘린더 화면 | 임베드로 표를 그리면 읽기 어렵다 |
| 반복 일정 | 2차. 규칙 입력 UI 가 커진다 |
| 실제 송금 연동 | 계좌·금융 API 는 범위 밖이다. **버튼은 "보냈다는 표시"** 일 뿐이다 |
| 환율·통화 | 원화만. 해외 결제는 사람이 환산해 적는다 |

## 6. 새 파일과 붙는 곳

```
src/plan/
  parse-when.js   "2026-10-03 18:30" · "10/3" → 시각.  verify 로 촘촘히 검사
  store.js        data/plans.json — 일정 저장 + 알림 예약 복구
  index.js        /일정 · 우클릭 등록 · 판 버튼
  settle.js       /정산 + data/settlements.json
```

- `FEATURES` 에 **`plan`** 하나를 추가한다. 일정과 정산을 같이 켜고 끈다 —
  둘을 따로 끌 이유가 없고, 토글이 늘면 아무도 안 만진다.
- 버튼 앞머리 **`pl:`** (일정) / **`st:`** (정산)
- `index.js` 에 **우클릭 명령어 처리**를 새로 붙인다 (`isMessageContextMenuCommand`)
- 고른 상태는 customId 에 싣는다 (3.6-8 과 같은 이유)

명령어 수: 15 → **16개** (`/일정`, `/정산` 은 2개지만 `/영화` 처럼 판 위주라 목록 부담이 적다).
정확히는 슬래시 17개 + 우클릭 1개.

## 8. 채널 생성 — **넣기로 결정. 구현됨**

**채널을 봇이 만들어줄까?**

지금은 사람이 `[yymmdd-일정명]` 채널을 만들고 참여자 권한을 준다. 이걸 봇이 대신할 수 있다.

```
/일정새로 이름:오사카 날짜:10/3 사람:@민수 @수현
  → 「일정」 카테고리 아래 [251003-오사카] 비공개 채널 생성
  → 고른 사람에게만 권한 부여
  → 그 채널에 일정 판을 바로 띄움
```

| | |
|---|---|
| 좋은 점 | 워크플로에서 **가장 반복되는 일**이 사라진다. 채널명 규칙도 자동으로 맞는다 |
| 걸리는 점 | 봇에 **`채널 관리` 권한**이 필요하다. 명령어가 하나 더 늘어난다. 카테고리를 어떻게 지정할지 정해야 한다 (`/채널설정` 에 항목 추가) |

소유자 결정: **넣는다. 사람뿐 아니라 역할로도 넣을 수 있어야 한다.**

`/일정새로` → 창(모달) 5칸: 이름 · 날짜 · 장소 · **참여자**(사람 고르기) · **참여 역할**(역할 고르기).
모달에 사람·역할 고르기 칸을 넣을 수 있어서 한 화면에서 끝난다.

- `[yymmdd-이름]` 으로 **지정한 카테고리 밑에** 만든다 (`/채널설정` 의 「일정 카테고리」)
- `everyone` 의 보기 권한을 **막고**, 고른 사람·역할·**만든 사람**에게만 열어준다
  (만든 사람을 빼먹으면 자기가 만든 채널을 못 본다)
- 봇에 `채널 관리` 권한이 없으면 **미리 알려준다.** 만들다 실패하면 원인을 알기 어렵다
