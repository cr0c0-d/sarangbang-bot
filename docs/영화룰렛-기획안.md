# 영화 추천/투표 기능 기획안 (`/영화뽑기`, `/영화투표`)

작성 대상 저장소: [sarangbang-bot](https://github.com/cr0c0-d/sarangbang-bot) (망고 · 노래하는 망고)
작성일: 2026-09-01

---

## 0. 한 문단 요약

친구들이 "오늘 뭐 볼지" 정할 때 쓰는 기능. **장르 + OTT(넷플릭스/쿠팡플레이 등)를 고르면
TMDB API로 그 조건에 맞는 영화 후보를 가져와서** (1) 즉시 한 편을 랜덤으로 뽑아주거나
(`/영화뽑기`), (2) 여러 편을 후보로 뽑아 기존 `/투표` 시스템에 넘겨 버튼 투표로 정하게
한다(`/영화투표`). 외부 유료 API 없음 — TMDB는 무료 API 키로 사용 가능.

---

## 1. 배경 및 목표

### 1.1 왜 필요한가

- 기존 `/투표`는 선택지를 사람이 일일이 입력해야 한다("오징어게임, 기생충, ..."을 직접 타이핑).
- 영화/드라마 목록을 찾아보는 것 자체가 귀찮아서 "아무거나 봐" → 결국 30분 허비.
- 특정 OTT(우리가 실제로 보는 넷플릭스/쿠팡플레이)에서 볼 수 있는 것만 추리고 싶다.

### 1.2 목표

1. 장르 + OTT를 지정하면 그 조건에 맞는 실제 콘텐츠를 자동으로 가져온다.
2. 고민 없이 바로 정하고 싶을 때 → 즉시 랜덤 1편.
3. 여러 명이 같이 고르고 싶을 때 → 후보군을 뽑아 기존 투표 버튼 UI로 넘긴다.
4. 기존 프로젝트 관례(비개발자 친구도 쓸 수 있게 명령어 최소화, 버튼 위주 UI)를 따른다.

### 1.3 하지 않는 것 (Non-goals)

- 넷플릭스/쿠팡플레이 **실시간 카탈로그 크롤링**은 하지 않는다 (공식 API 없음, 계정 차단
  리스크, 유지보수 부담 — 3.1절 참고).
- 실제 재생/딥링크 연결은 하지 않는다. "이 작품 보세요" 안내까지만 한다.
- 개인 시청 이력 추적이나 별점 저장 같은 기능은 이번 범위에 넣지 않는다 (필요해지면
  별도 기획).

## 2. 사용자 시나리오

```
[시나리오 A] 그냥 빨리 정하고 싶을 때
/영화뽑기 장르:코미디 OTT:넷플릭스
→ 봇이 조건에 맞는 것 중 1편을 즉시 뽑아 포스터+줄거리+평점을 보여줌
→ "다시뽑기" 버튼 누르면 다른 한 편으로 교체

[시나리오 B] 여럿이 같이 고르고 싶을 때
/영화투표 장르:스릴러 OTT:쿠팡플레이 개수:4
→ 조건에 맞는 4편을 뽑아 기존 투표 UI(버튼)로 띄움
→ 각자 버튼 눌러 투표, 마감하면 최다 득표작 확정
```

## 3. 기술 조사 결과

### 3.1 왜 넷플릭스/쿠팡플레이에 직접 연결하지 않는가

| 방법 | 문제 |
| --- | --- |
| 공식 API | 두 서비스 다 서드파티용 카탈로그 조회 API를 제공하지 않음 |
| 비공식 크롤링 | 이용약관 위반 소지, 구조 변경 시 수시로 깨짐, 계정/IP 차단 위험 |
| → 채택: TMDB | 무료, 공식 API, 지역별 OTT 제공 정보(JustWatch 데이터 기반) 포함 |

### 3.2 TMDB (The Movie Database) API

- 무료 API 키 발급 (가입 즉시).
- `GET /discover/movie`, `GET /discover/tv` — 장르·지역·OTT 제공자로 필터링 가능.
- `watch_region=KR` + `with_watch_providers=<제공자ID>` 조합으로 **"한국에서 이 OTT로
  볼 수 있는 작품"** 목록을 가져올 수 있다.
- 주요 제공자 ID (KR 기준, 실 사용 전 `/watch/providers/movie?watch_region=KR` 로
  최신값 재확인 필요):

  | OTT | provider_id (참고용, 확정 전 재조회 필요) |
  | --- | --- |
  | 넷플릭스 | 8 |
  | 쿠팡플레이 | 356 |
  | 웨이브 | 356 계열과 별도 확인 필요 |
  | 왓챠 | 확인 필요 |

  > ⚠️ TMDB의 provider ID는 지역·시점에 따라 바뀔 수 있으므로, 구현 시작 시점에
  > `/watch/providers/movie?watch_region=KR`을 한 번 호출해 실제 값을 확정하고 코드에
  > 상수로 박아둔다 (sarangbang-bot이 유튜브 provider quirks를 실측해서 문서화하는
  > 방식과 동일하게, 이것도 실측 후 표로 남길 것).

- 응답 필드: 제목, 포스터 경로(`poster_path`), 줄거리(`overview`), 평점(`vote_average`),
  개봉일 등. 포스터 전체 URL은 `https://image.tmdb.org/t/p/w500{poster_path}`로 조립.

### 3.3 영화(movie) vs 드라마/시리즈(tv) 구분

- TMDB는 영화와 TV 시리즈를 **별도 엔드포인트**로 다룬다(`/discover/movie`,
  `/discover/tv`).
- 사용자 입장에서는 "영화든 드라마든 상관없이 재밌는 거"를 원할 가능성이 높으므로,
  기본은 **둘 다 조회해서 합친 뒤 랜덤**으로 두고, 필요하면 `종류:영화 / 시리즈` 옵션을
  추가로 열어둔다 (1차 구현에서는 생략 가능 — 아래 4.3 "생략 가능한 것" 참고).

## 4. 명령어 설계

### 4.1 `/영화뽑기` — 즉시 랜덤 1편

| 옵션 | 필수 | 설명 |
| --- | --- | --- |
| `장르` | 예 | 자동완성으로 TMDB 장르 목록 제공 (코미디/액션/로맨스/스릴러/공포/애니메이션 등) |
| `ott` | 예 | 자동완성: 넷플릭스 / 쿠팡플레이 / (추가 가능) |

**동작**

1. TMDB discover 호출 (장르+OTT+`watch_region=KR` 필터, 평점순 또는 인기순 정렬,
   상위 N페이지 정도 확보).
2. 후보 중 1편을 무작위로 선택.
3. 임베드로 응답: 포스터(썸네일 또는 큰 이미지) + 제목 + 평점 + 줄거리(길면 축약)
   + "🎲 다시뽑기" 버튼.
4. 버튼을 누르면 같은 조건으로 재추첨 (직전에 뽑았던 작품은 제외해서 연속 중복 방지).

**참고할 기존 관례**: 음악 제어판(`music/panel.js`)처럼 버튼 하나로 재시도가 되는 구조.
새 명령어를 늘리지 않고 버튼으로 해결하는 프로젝트 원칙(3.6-6절)을 따른다.

### 4.2 `/영화투표` — 후보군을 뽑아 기존 투표로 연결

| 옵션 | 필수 | 설명 |
| --- | --- | --- |
| `장르` | 예 | 위와 동일 |
| `ott` | 예 | 위와 동일 |
| `개수` | 아니오 (기본 4) | 후보 몇 편을 뽑을지, 최대 5 (기존 `/투표`가 사진 5개까지 지원하므로) |

**동작**

1. TMDB discover로 후보 여러 편 확보 후 무작위로 `개수`만큼 중복 없이 선정.
2. 각 후보의 포스터 이미지를 다운로드.
3. 기존 `poll` 모듈의 투표 생성 로직을 재사용해서, 질문("오늘 뭐 볼까?")과
   선택지(영화 제목들) + 포스터 이미지로 투표 메시지 생성.
4. 이후 흐름(버튼 투표, 익명 집계, 마감)은 **기존 `/투표` 기능을 그대로 재사용** —
   새로 만들 필요 없음.

> ⚠️ 기존 `/투표`가 첨부 이미지를 "만료되는 URL이 아니라 다시 업로드해서 붙이는"
> 방식(3.6-7절)을 쓰고 있으므로, TMDB 포스터도 URL을 그대로 임베드에 박지 말고
> **다운로드 후 `AttachmentBuilder`로 재업로드**해야 한다. 이 부분에서 기존 poll 생성
> 함수를 그대로 호출할 수 있는지, 아니면 poll 내부 로직 일부를 함수로 분리해서 공유해야
> 하는지는 구현 시 `poll/index.js` 구조를 보고 결정.

### 4.3 1차 구현에서 생략 가능한 것 (나중에 추가)

- 영화/드라마 종류 구분 옵션
- "최근 본 것 제외" 히스토리 (음악의 지난 재생 목록과 비슷한 개념이지만 범위 밖)
- 세부 필터(연도, 최소 평점 등)
- OTT 목록 확장 (웨이브/왓챠/디즈니+ 등) — provider ID만 추가하면 되므로 기술적 장벽은
  낮음, 우선순위 문제

## 5. 데이터/설정 추가 사항

### 5.1 환경변수 (`.env`)

```
TMDB_API_KEY=<발급받은 키>
```

### 5.2 새 파일 구조 (제안)

```
src/movie/
  tmdb.js               TMDB API 호출 공용 함수 (discover, 장르 목록, provider 목록)
  roulette-commands.js  /영화뽑기 명령어 + 다시뽑기 버튼 핸들러
  vote-commands.js      /영화투표 명령어 (poll 모듈 호출)
```

- 기존 프로젝트 관례상 기능별 폴더 분리(`music/`, `tts/`, `images/`, `poll/`)를 따라
  `movie/`로 새 폴더를 둔다.
- `commands.js`에서 `tag('movie', movieCommands)`로 등록하고, `/기능` on/off 패널에도
  자동으로 편입되게 한다(기존 `FEATURES` 표 방식 재사용, 3.7-1절).

### 5.3 캐시 여부

- 장르 목록, provider 목록은 자주 바뀌지 않으므로 시작 시 한 번 가져와 메모리에
  캐시(24시간 정도)해두면 API 호출을 아낄 수 있다. 필수는 아니고 최적화 항목.
- 영화 후보 자체는 캐시하지 않는다 — "새로 뽑을 때마다 다른 결과"가 기능의 핵심이므로.

## 6. 예외 처리

| 상황 | 처리 |
| --- | --- |
| 해당 장르+OTT 조합에 결과가 0건 | "조건에 맞는 작품이 없어요" 안내, 조건 완화 제안 |
| TMDB API 호출 실패/타임아웃 | 에러 안내 + 재시도 버튼 (음악 쪽 `friendlyError()` 관례처럼 원인을 구체적으로 알림) |
| `개수`가 실제 후보 수보다 많음 | 있는 만큼만 뽑고 몇 편인지 안내 (재생목록 자르기 안내와 동일한 원칙 — 3.1-1절) |
| 포스터 이미지가 없는 작품 | 기본 이미지로 대체하거나 텍스트만으로 표시 |

## 7. 단계별 구현 순서 (제안)

1. **TMDB 연동 기초**: `tmdb.js` — API 키 설정, discover 호출, 장르/provider ID 확정
   (실측 후 표로 문서화).
2. **`/영화뽑기`(즉시 랜덤)** 먼저 구현 — 가장 단순하고 기존 poll 의존성이 없음.
3. **`/영화투표`** — poll 모듈과의 연동 지점 확인 후 구현.
4. `/기능` 패널에 편입, `/도움말`에 문구 추가.
5. `verify.mjs`에 회귀 검사 추가 (선택지 파싱, provider ID 유효성 등 — 기존 검증 철학
   유지).

## 8. 열린 질문 (구현 전 결정 필요)

- 넷플릭스/쿠팡플레이 외에 추가로 넣고 싶은 OTT가 있는지
- `/영화투표` 최대 후보 수를 5로 고정할지(기존 투표 사진 5장 제한과 맞춤), 사진 없이
  텍스트만 더 넣을지
- 영화/드라마를 분리할지, 처음부터 섞어서 뽑을지
