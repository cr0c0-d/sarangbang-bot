# 🎭 읽어주기 감정 표현 — AI 음성 생성 검토

> **상태: 검토만. 구현하지 않았습니다.**
> 소유자 요청: *"음성 자체를 AI로 만드는 방식에 대해 검토만 일단 해줘"*
>
> ⚠️ **여기 적은 것 중 실제로 돌려본 것은 지금 쓰는 Edge 엔드포인트뿐입니다.**
> 나머지 넷은 **키가 없어 문서·공개 정보만 봤습니다.** 어느 것이 실제로 한국어를
> 잘 읽는지는 **직접 들어봐야** 알 수 있습니다. 이 저장소에서 실측 밖으로 결론을
> 늘렸다가 두 번 사고가 났으므로(ARCHITECTURE 3.6-11 1절), 그 경계를 표에 표시했습니다.

## 0. 소유자가 본 것

> "다른 봇에서는 음성 자체를 AI로 만드는 것 같더라고. (…) 느낌표 세개를 붙이면
> 진짜 연기하는것처럼 자연스럽게 소리지르더라고. 그 기능이 재밌었어서 구현해보면 좋겠어."

**그 봇이 무엇을 썼는지는 모릅니다.** 다만 "느낌표 3개 → 자연스럽게 소리지름" 을 낼 수
있는 기술은 몇 개로 좁혀집니다. 아래 3절이 그 목록입니다.

가장 그럴듯한 것은 **ElevenLabs v3 의 오디오 태그**입니다. `[shouts]` 같은 태그를
문장에 끼워 넣으면 그렇게 연기해줍니다 — `!!!` 를 감지해 태그로 바꾸기만 하면
소유자가 본 동작이 그대로 나옵니다.

## 1. ★ 왜 지금은 안 되는가 (실측)

**지금 쓰는 것은 Edge 브라우저의 "소리내어 읽기" 엔드포인트입니다** (`msedge-tts`).
공짜이고 키가 필요 없는 대신, 표현력이 거의 없습니다. 2026-09-08 에 직접 재봤습니다.

### 받아주는 SSML이 **평평한 `<prosody>` 하나뿐**입니다

| 보낸 것 | 결과 |
|---|---|
| `<prosody pitch rate volume>` | ✅ 유일하게 통과 |
| `<mstts:express-as style="angry">` (angry·shouting·excited) | ❌ 연결이 끊김 |
| `<break time="350ms"/>` | ❌ 연결이 끊김 |
| `<emphasis>` · `<say-as>` · `contour` · 중첩 `prosody` | ❌ 연결이 끊김 |

새 프로세스에서 **첫 요청**으로 보내도 같으므로 호출 한도가 아니라 **내용** 때문입니다.

### 그 `<prosody>` 안에서도 폭이 작습니다

`ko-KR-SunHiNeural`, 문장 `아니 이게 뭐야 진짜`. 기본주파수는 자기상관으로,
볼륨은 ffmpeg `volumedetect` 로 측정.

| prosody | 기본주파수 | 평균 볼륨 |
|---|---|---|
| (없음) | 208Hz | -18.4dB |
| `pitch="+35Hz" volume="+25"` ← **없앤 기능** | 254Hz | -16.6dB |
| `pitch="+200Hz"` | 308Hz (포화) | -18.4dB |
| `volume="x-loud"` | — | **-18.5dB (변화 없음)** |

**없앤 기능이 올린 것은 46Hz(22%)와 1.8dB 뿐**이고, 그것도 문장 전체에 똑같이 걸립니다.
소유자가 *"실제로는 별 차이가 없더라구"* 라고 한 것이 정확합니다.

### 그리고 목소리 자체에 감정이 없습니다

무료 엔드포인트의 목소리 목록을 받아봤습니다 — **322개 전부 `StyleList` 가 없고**,
한국어는 **3개뿐**입니다.

| 목소리 | VoiceTag |
|---|---|
| `ko-KR-HyunsuMultilingualNeural` | `Friendly, Positive` |
| `ko-KR-InJoonNeural` | `Friendly, Positive` |
| `ko-KR-SunHiNeural` | `Friendly, Positive` |

★ **중요:** Microsoft 문서를 확인해보니 **유료 Azure 에서도 이 세 목소리는 스타일을
지원하지 않습니다.** 즉 돈을 낸다고 지금 목소리에 감정이 붙는 게 아니라, **목소리를
바꿔야** 합니다 (아래 3.1).

## 2. "음성 자체를 AI로 만든다" 가 무슨 뜻인가

지금 방식과 새 방식의 차이는 이렇습니다.

| | 지금 (Edge) | 새 방식 |
|---|---|---|
| 무엇을 보내나 | 글 + `<prosody>` 숫자 | 글 + **"어떻게 읽어라" 는 말이나 태그** |
| 표현 조절 | 음높이·속도를 기계적으로 비틈 | **모델이 연기를 생성** |
| 예 | `pitch="+35Hz"` | `[shouts]` · `"화나서 소리치듯"` |

두 갈래가 있습니다.

- **스타일 목록형** — 미리 정해둔 감정 이름을 고릅니다 (`angry`, `excited`).
  예측 가능하지만 목록에 없는 건 못 합니다. → Azure
- **자유 지시형** — 사람 말로 지시합니다 (`"화가 나서 소리치듯, 끝을 흐리며"`).
  훨씬 유연하지만 결과가 매번 조금씩 다릅니다. → Gemini · OpenAI · ElevenLabs(태그)

소유자가 본 "진짜 연기하는 것처럼" 은 **후자**의 특징입니다.

## 3. 후보 비교

> 🔴 = 문서·공개 정보만 봤고 **직접 들어보지 않았습니다.**

| | 한국어 감정 | 가격 | 무료 | 한국어 품질 | 계정 만들기 |
|---|---|---|---|---|---|
| **Azure Speech** | 🔴 목소리 **2개**만 (angry·excited 등, **shouting 없음**) | $22 / 100만자 (Neural HD) | 🔴 월 50만자 | 🔴 미확인 (지금 목소리와 같은 회사) | 어려움 (Azure 구독) |
| **Gemini TTS** | 🔴 사람 말로 지시 | ~$10 / 100만 오디오토큰 (≈분당 $0.015) | 🔴 **하루 15회** | 🔴 미확인 | **쉬움 — 키가 이미 있습니다** |
| **ElevenLabs v3** | 🔴 `[shouts]` 등 오디오 태그 | $0.05 / 1000자 (+구독 $5~) | 없음 | 🔴 미확인 (74개 언어) | 보통 |
| **OpenAI TTS** | 🔴 `instructions` 로 지시 | ~$12 / 100만 오디오토큰 | 없음 | 🔴 **영어에 최적화** 라고 명시 | 보통 |

### 3.1 Azure — 지금 쓰는 목소리의 유료판, 그런데 목소리를 바꿔야 함

문서에서 확인한 한국어 스타일 지원 목소리는 **딱 둘**입니다.

| 목소리 | 되는 스타일 |
|---|---|
| `ko-KR-Haena:MAI-Voice-2` (여) | angry · confused · determined · embarrassed · **excited** · happy · hopeful · joyful · regretful · relieved · sad · softvoice · surprised |
| `ko-KR-Junho:MAI-Voice-2` (남) | angry · confused · determined · embarrassed · **excited** · happy · hopeful · joyful · relieved · sad · softvoice |

- ⚠️ **`shouting` 은 한국어에 없습니다.** 소리지르기는 `angry` + `excited` 로 흉내내야 합니다.
- ⚠️ 지금 쓰는 SunHi·Hyunsu·InJoon 은 **여기 없습니다.** 감정을 쓰려면 목소리가 바뀝니다.
- ✅ **월 50만자 무료**가 후보 중 가장 큽니다. 아래 4절 계산으로는 그것만으로 충분합니다.
- ⚠️ 무료 등급에 **Neural HD 가 포함되는지는 확인하지 못했습니다.** (Haena·Junho 가 HD 등급)

### 3.2 Gemini — 키가 이미 있다, 그런데 하루 15회

**소유자 서버에 `GEMINI_API_KEY` 가 이미 있습니다** (망고야가 씁니다). 붙이는 마찰이 가장 작습니다.

- ✅ 사람 말로 지시합니다. 문장 중간에 태그로 톤을 바꾸는 것도 된다고 합니다.
- ⚠️ **무료 등급이 하루 15회 · 분당 3회입니다.** 시험해보기엔 되지만 **쓸 수는 없습니다.**
- ⚠️ 전부 **preview** 라 SLA 가 없고 예고 없이 바뀔 수 있습니다.
- 한도는 모델별로 매겨지므로 망고야 한도를 갉아먹지는 않을 것으로 보이지만,
  계정 단위 정책이 겹칠 수 있어 **확인이 필요합니다.**

### 3.3 ElevenLabs — 소유자가 본 것에 가장 가까움

`[shouts]` `[laughs]` `[whispers]` 같은 태그를 문장에 끼워 넣습니다.
**`!!!` → `[shouts]` 치환 하나로 본 동작이 나옵니다.** 표현력 평판이 가장 좋습니다.

- ⚠️ 무료 등급이 없습니다. 구독이 $5/월부터입니다.
- ⚠️ 태그가 목소리 성격과 충돌하면 **부자연스러워질 수 있다**고 문서가 스스로 경고합니다.

### 3.4 OpenAI — 싸지만 한국어가 의문

`instructions` 칸에 `"화가 나서 소리치듯"` 을 넣습니다. 값이 싸고 붙이기 쉽습니다.

- ⚠️ 문서가 **"영어에 최적화"** 라고 명시합니다. 한국어 이름·숫자는 실제 대본으로
  시험해보라고 스스로 권합니다. **이 프로젝트는 전부 한국어입니다.**

### 3.5 안 본 것

**국내 서비스**(네이버 클로바 · 타입캐스트 · 수퍼톤)는 이번에 보지 않았습니다.
한국어 감정 표현은 이쪽이 더 나을 가능성이 있습니다. 필요하면 따로 조사하겠습니다.

## 4. 돈이 얼마나 드나

두 가지 쓰는 방식으로 계산했습니다. 메시지 하나를 40자·3초로 잡았습니다.

### ㄱ. 느낌표 3개짜리만 새 엔진 (하루 30번 = 월 900번)

| | 월 비용 |
|---|---|
| **Azure** | 3.6만자 → **무료 한도 안 (0원)** |
| **Gemini** | 45분 → 약 **$0.7** (무료 하루 15회로는 절반만) |
| **ElevenLabs** | 3.6만자 → 약 **$1.8** + 구독 $5 |
| **OpenAI** | 45분 → 약 **$0.7** |

### ㄴ. 읽어주기 전체를 새 엔진으로 (하루 300개 = 월 9000개)

| | 월 비용 |
|---|---|
| **Azure** | 36만자 → **무료 한도 안 (0원)**, 넘으면 100만자당 $22 |
| **Gemini** | 750분 → 약 **$11** (무료 등급 무의미) |
| **ElevenLabs** | 36만자 → 약 **$18** |
| **OpenAI** | 750분 → 약 **$11** |

> ⚠️ **메시지 수는 제가 모릅니다.** 위 숫자는 가정입니다. 실제 하루 읽어주기 횟수를
> 알려주시면 다시 계산하겠습니다. 지금 봇은 그 횟수를 세지 않습니다 —
> 붙이기 전에 **세는 것부터** 넣는 게 안전합니다 (망고야 한도 장치와 같은 생각).

**Azure 의 월 50만자 무료가 후보 중 압도적입니다.** 계정 만들기가 가장 번거로운 대신,
가정한 규모에서는 **전체를 바꿔도 0원**입니다.

## 5. ★ 권하는 모양 — 하이브리드

**평소는 지금 그대로 Edge, 느낌표 3개일 때만 감정 엔진.**

```
읽어줄 글
  ↓
느낌표 3개 이상? ──아니오──→ Edge (지금 그대로 · 무료 · 예열된 웹소켓)
  │
  예
  ↓
감정 엔진 (Azure angry+excited / ElevenLabs [shouts] / …)
  │
  실패하면 ──────────────→ Edge 로 그냥 읽음
```

이유가 넷입니다.

1. **비용이 100분의 1이 됩니다.** 전체 메시지의 몇 %만 유료 엔진을 씁니다.
2. **지연이 그 메시지에만 붙습니다** (6절).
3. **감정 엔진이 죽어도 읽어주기는 계속됩니다.** 키가 없거나 한도를 넘겨도
   평소 동작이 그대로 남습니다 — 이 저장소가 늘 지키는 방식입니다
   (스팀 검색이 죽어도 직접 입력은 살아 있는 것과 같습니다).
4. **한도 초과를 감정 쪽만 잃는 것으로 끝냅니다.**

### 다만 하이브리드의 대가

**목소리가 갑자기 바뀝니다.** 평소 SunHi 로 읽다가 소리지를 때만 Haena 가 되면
"다른 사람이 소리치는" 느낌이 됩니다.

두 갈래입니다.

- **ㄱ. 그대로 받아들인다** — "흥분하면 목소리가 변한다" 는 연출로 쓸 수도 있습니다.
- **ㄴ. 평소도 같은 엔진으로 바꾼다** — Azure 라면 무료 한도로 커버되므로
  **Haena/Junho 하나로 평소·소리지르기를 다 처리**할 수 있습니다. 목소리가 일관됩니다.
  Edge 는 **키가 없거나 한도를 넘겼을 때의 대비책**으로 남깁니다.

→ **ㄴ 이 더 낫다고 봅니다.** 단, 소유자와 친구들이 **Haena/Junho 목소리를 들어보고
마음에 들어야** 합니다. 지금 목소리와 다릅니다.

## 6. ★ 진짜 위험은 돈이 아니라 지연입니다

지금 읽어주기는 **웹소켓을 미리 열고 예열해둡니다** (`prewarm` + keepalive).
그래서 첫 글자부터 바로 나옵니다. 누가 음성채널에 들어오면 미리 데우기까지 합니다.

**HTTP API 로 바꾸면 그 예열이 사라집니다.** 매번 새 HTTPS 왕복입니다. 게다가
소유자 서버는 **1코어 ARM + 해외 요청**입니다 — 자동완성도 "약간 시간 걸린다" 고
하신 그 환경입니다.

⚠️ **얼마나 걸릴지 재보지 않았습니다.** 붙이기 전에 **가장 먼저 재야 할 것**이 이겁니다.
채팅을 읽어주는 기능이라 1~2초만 늘어도 "느리다" 가 됩니다.

하이브리드가 여기서도 유리합니다 — **느낌표 문장만 기다립니다.**

## 7. 붙이는 비용은 작습니다 (확인함)

엔진을 갈아 끼우는 자리가 **함수 하나**입니다.

```
synthesize(text, voice, speedPercent) → mp3 스트림
        ↓
audio.speak(...) → toOggOpus → 디스코드
```

부르는 곳이 **두 군데뿐**입니다 — `tts/index.js:257`, `timer/index.js:207`.
그 뒤는 ffmpeg 이 어떤 오디오든 Ogg Opus 로 바꿔주므로 **mp3 를 돌려주기만 하면**
나머지는 손댈 필요가 없습니다.

즉 **어려운 건 코드가 아니라 고르는 일**입니다.

## 8. 확인하지 않은 것 (붙이기로 정하면 이것부터)

1. **한국어를 실제로 잘 읽는지** — 넷 다 못 들어봤습니다. **이게 제일 중요합니다.**
   특히 OpenAI 는 문서가 스스로 "영어 최적화" 라고 합니다.
2. **1코어 ARM 에서 몇 초 걸리는지** (6절). 배수를 추측하지 않겠습니다.
3. **Azure 무료 등급에 Neural HD(Haena·Junho)가 포함되는지.**
4. **Gemini TTS 한도가 망고야 한도와 겹치는지.**
5. **하루 읽어주기 횟수** — 소유자만 알 수 있습니다. 비용 계산의 전제입니다.
6. **국내 서비스**(클로바·타입캐스트·수퍼톤) — 아예 안 봤습니다.

대비책으로 남기는 것(5절 ㄴ). 무료 한도로 커버되고 목소리도 일관됩니다.
ⓑ 계정 만들기가 부담이면 **ElevenLabs 로 느낌표만** — 소유자가 본 동작에 가장 가깝고
월 $5~6 으로 끝납니다.

다만 **어느 쪽이든 먼저 목소리를 들어보고 지연을 재봐야** 합니다.
들어보기는 계정 없이도 각 서비스 웹 데모로 됩니다 — 그게 가장 싼 다음 단계입니다.
