# 🎮 게임 검색 + 포럼 연동 기획안

방송 기록(타임머신)에 **게임을 정확히 붙이고**, 지금 손으로 하는
**녹화 포럼 · 스샷 포럼 정리를 봇이 하게** 만드는 기획입니다.

작성일: 2026-09-03 · **Phase A~C 핵심 범위 구현 완료 (2026-09-03)**
최신 개정: 2026-09-04 — 한글 별칭·수동 별칭·녹화방 타임라인 동기화 반영. 실제 Discord 연동은 운영 확인 필요.
검증: 자체 검사 1,177개 통과. 설명 입력창→공유 방송자 녹화방, 페이지 증감, 부분 전송 실패 복구를 가짜 Discord 클라이언트로 확인했습니다.
담당 봇: **망고** (`BOT_ROLE=mango`) · 관련: [게임방송-기획.md](게임방송-기획.md)

## 0. 하려는 것 (소유자 요청 원문)

> "게임을 검색하는 기능을 만들 수 있나? 보통 스팀게임을 자주하기 때문에 스팀에 있는
> 게임이면 돼. 목록에 없으면 게임명을 직접 입력할 수 있게 하고."

> "지금은 녹화 포럼채널과 스샷 포럼채널을 만들어서, 게임별로 포스트를 작성하고
> 그 포스트에 해당 게임의 라이브 링크랑 스샷을 각각 모으고 있거든.
> 이것도 연결할 수 있으면 좋겠어."

즉 두 개입니다. **둘 다 "게임" 을 열쇠로 씁니다** — 그래서 한 문서에 담습니다.

---

## 1. ★ 먼저 정해야 하는 것 — **게임은 세션의 것인가, 사람의 것인가**

이게 아래 모든 것을 정합니다. 미루면 안 됩니다.

초기 구현의 `session.game` 은 **세션 하나에 하나**였습니다. 그런데 소유자가 말했습니다:

> "동시에 방송은 켰지만 각자 다른 게임을 하고 있을 수도 있거든."

이 말 때문에 마킹은 이미 **사람 것**으로 바꿨습니다 (`mark.forUserId`).
**게임도 같은 문제를 그대로 안고 있습니다.** 민수가 발하임, 지예가 Lethal Company 를
하는데 세션에 게임이 하나면:

- 민수의 라이브 링크가 **Lethal Company 포스트에** 올라갈 수 있습니다.
- 요약판 제목도 틀립니다.
- 스샷도 엉뚱한 포스트로 갑니다.

**결론: 게임은 `stream` 에 둡니다. 세션에도 남기지만 "그날의 대표 이름" 일 뿐입니다.**

```
session.game        ← 그날 이름 (첫 등록자가 정함). 표시·검색용
stream.game         ← ★ 실제 판단 기준. 포스트 찾기·요약판 제목에 이걸 씀
stream.appid        ← 스팀 앱 번호. 있으면 이름이 흔들려도 같은 게임으로 알아봄
```

`stream.game` 이 없으면 `session.game` 으로 물러납니다. 그래서 혼자 할 때는 아무것도 안 바뀝니다.

⚠️ 이건 **자료 구조를 바꾸는 일**이라 Phase 1 의 맨 앞입니다. 나중에 끼워넣으면
포스트가 이미 잘못 만들어져 있습니다.

## 2. 실측 결과 — 무엇이 되고 무엇이 안 되는가

추측이 아니라 직접 돌려본 것만 적습니다 (2026-09-03).

### 2.1 스팀 검색 — 키 없이 됩니다

```
$ curl "https://steamcommunity.com/actions/SearchApps/valheim"
[{"appid":"892970","name":"Valheim","icon":"https://…","logo":"https://…"}]
```

- **API 키가 필요 없습니다.** 가입도 없습니다.
- 최대 **10개**를 줍니다. (`lethal` → 10개: Lethal Company, Lethal League Blaze, …)
- 응답이 가볍고 빠릅니다.

### 2.2 게임 정보도 키 없이 됩니다

```
$ curl "https://store.steampowered.com/api/appdetails?appids=1966720&cc=kr&l=korean"
{ "name": "Lethal Company", "type": "game",
  "header_image": "https://…/apps/1966720/header.jpg",
  "genres": ["액션","어드벤처","인디","앞서 해보기"],
  "categories": ["싱글 플레이어","멀티플레이어","협동","온라인 협동", …] }
```

- 장르·카테고리는 **한국어로** 옵니다. 임베드에 쓸 `header_image` 도 있습니다.
- **`협동` 카테고리**가 있으니 "같이 하는 게임" 판별에 쓸 수 있습니다.

### 2.3 ⚠️ Steam 원격 검색의 한글 한계 — 로컬 별칭으로 보완

```
$ curl "https://steamcommunity.com/actions/SearchApps/발하임"
[]
```

**빈 배열입니다.** 아직 저장하지 않은 Steam 게임은 영문으로 찾습니다.
그리고 게임 이름도 늘 한국어로 오지 않습니다 — Lethal Company 는 `name` 이
한국어 요청에도 영문 그대로였습니다.

→ 포럼을 연결할 때 제목을 `data/game-aliases.json`에 게임 키와 함께 저장합니다.
이후 `/게임`·`/방송`에서 한글 일부로 검색해 같은 Steam 게임을 고를 수 있습니다.
스레드 관리자는 `/게임 검색:<게임> 별칭:스듀`처럼 줄임말도 저장합니다.
띄어쓰기·문장부호·이모지는 검색 시 무시하며, 서버별로 저장해 재시작 후에도 유지합니다.
별칭이 겹치면 자동 확정하지 않고 목록에서 고르게 합니다. 제미나이는 호출하지 않습니다.
Steam에 없는 게임(콘솔·모바일)은 직접 입력 경로를 유지합니다.

### 2.4 ⚠️ 두 주소 모두 **비공식**입니다

문서화된 API 가 아닙니다. 언제든 바뀔 수 있습니다.
`yt-dlp`(3.1)와 같은 판단을 합니다 — **깨질 것을 알고 쓰되, 깨졌을 때 기능이 죽지 않게** 합니다.

```
검색이 깨짐 → 자동완성 목록이 비어 보임 → 직접 입력은 그대로 됨 → 기능이 나빠질 뿐 죽지 않음
```

⚠️ 영화 기능(3.6-8)에서 **크롤링을 거부**한 것과는 다릅니다. 저건 HTML 을 긁는 것이고
이건 JSON 을 주는 엔드포인트입니다. 그래도 비공식인 건 같으니 **없어도 돌아가게** 만듭니다.

### 2.5 포럼 채널 — discord.js 14.27 에서 됩니다

```
ChannelType.GuildForum = 15 · GuildMedia = 16 · PublicThread = 11
ForumChannel -> ThreadOnlyChannel -> GuildChannel -> BaseChannel
GuildForumThreadManager.prototype.create = function   ← 포스트를 만들 수 있음
availableTags                                          ← 태그도 읽을 수 있음
```

### 2.6 ★ 스샷 포럼은 **이미 절반이 동작합니다**

이건 확인하고 놀랐습니다. 지금 코드가 이미 이렇게 되어 있습니다.

```js
// src/images/commands.js:35
const parentId = message.channel?.isThread?.() ? message.channel.parentId : null;
if (!imageChannelAllowed(message.guildId, message.channelId, parentId)) return false;

// src/images/store.js:127  resolveFolder()
if (channel?.isThread?.() && channel.name) return safeFolderName(channel.name);
```

- **스레드에 올린 사진도 부모 채널이 대상이면 저장됩니다** (`parentId` 를 실제로 넘깁니다).
- 그리고 **폴더 이름을 스레드 이름으로 씁니다.**

→ 현재는 `/채널설정`의 **스샷 포럼**으로 지정하면 해당 포스트의 사진을 자동 저장합니다.
별도 이미지 채널 허용 목록보다 우선하지만, 명시적으로 제외한 채널은 저장하지 않습니다.

### 2.7 포럼 전용 설정을 추가한 이유

초기에는 아래 두 가지가 막았습니다.

```js
// channel-commands.js
const TEXT_TYPES = [ChannelType.GuildText, ChannelType.GuildAnnouncement];  // 포럼 없음
if (spec.kind === 'text' && !channel.isTextBased?.()) return '…채팅창이 없습니다';
```

**`ForumChannel.isTextBased()` 는 false 입니다.** 포럼 자체에는 메시지를 못 보내고
포스트(스레드)에만 보낼 수 있기 때문입니다. 그래서 `kind: 'text'` 검사가 거부합니다.

→ 현재 **`kind: 'forum'`으로 녹화·스샷 포럼을 따로 지정합니다.** `kind: 'text'` 를 느슨하게 풀면 안 됩니다 —
읽어주기 채널에 포럼을 고를 수 있게 되고, 그건 동작하지 않습니다.

## 3. 쓰는 흐름 (UX)

### 3.1 게임 고르기 — **자동완성**. 새 명령어를 만들지 않습니다

`/방송` 의 `게임명` 칸에 자동완성을 붙입니다.

```
/방송 링크:https://youtube.com/live/… 게임명:leth
                                              ↓ 목록이 뜸
                                        🎮 Lethal Company
                                        🎮 Lethal League Blaze
                                        🎮 Lethal Dungeon
```

**왜 자동완성인가:**

- 명령어를 새로 만들지 않습니다 (규칙 3.6-6 — 명령어가 30개까지 불어나 한 번 걷어냈습니다).
- **단계가 늘지 않습니다.** 지금도 `게임명` 을 치던 자리에서 그냥 목록이 뜰 뿐입니다.
- **목록에 없으면 그냥 타이핑하고 넘어가면 됩니다.** 자동완성은 제안일 뿐이고,
  디스코드는 사용자가 **친 글자를 그대로** 보냅니다.
  이 저장소에 선례가 있습니다 — `/타이머` 가 이미 그렇게 씁니다
  (`src/timer/index.js`: 등록어·기본값 목록을 주면서, 직접 친 값이 시간으로 읽히면
  그것도 후보로 올립니다).

**값을 어떻게 실어 보내는가:**

| | 보이는 것(`name`) | 실제 값(`value`) |
|---|---|---|
| 목록에서 고름 | `Lethal Company` | `steam:1966720` |
| 직접 입력 | (목록 없음) | `모여봐요 동물의 숲` |

제출 시 서버에 저장된 게임 키·정확한 별칭을 먼저 찾습니다. 없고 `^steam:(\d+)$`이면
앱 번호로 이름·이미지를 조회합니다. 그 외 입력은 별도 직접 입력 게임으로 취급합니다.

⚠️ **자동완성은 글자마다 발생하고 디스코드는 3초를 줍니다.** 매 글자마다
`steamcommunity.com` 을 부르면 느리고, 비공식 엔드포인트에 예의도 아닙니다.
→ **2글자 미만이면 부르지 않고**, 검색어 앞자리로 **메모리 캐시**를 둡니다.
이건 자세한 사항이 아니라 **설계 제약**입니다.

### 3.2 늦게 정하거나 바꾸기

방송 중에 게임이 바뀔 수 있습니다 (그래서 하루에 여러 세션이 됩니다).

- `/방송 게임명:…`을 다시 실행합니다 (링크 없이 = 등록된 내 게임만 바꿈).
- 별도 게임 선택 버튼/모달은 만들지 않았습니다. `지난 게임으로 등록` 버튼은 저장 주소와 마지막 게임을 재사용합니다.

### 3.3 녹화 포럼 — 라이브 링크를 게임별 포스트에 모읍니다

`/채널설정` 에 **녹화 포럼** 을 지정합니다. 방송 종료 시:

1. 그 사람의 게임에 해당하는 **포스트를 찾습니다** (4.2 — id 로 찾습니다).
2. 연결된 포스트가 없으면 **기록을 보류합니다. 새 포스트는 만들지 않습니다.**
3. 연결된 포스트에는 방송자·시작 날짜·라이브 링크·타임라인을 올립니다. 시작 날짜에 요일·시간은 표시하지 않습니다.

```
📺 2026-09-03 · @민수
https://www.youtube.com/watch?v=xxxxxxxxxxx
```

타임라인 설명은 **본인의 나만 보기 요약판에서 수정하고 공유 녹화방에 동기화**합니다.
녹화방 유튜브 URL은 미리보기를 숨기는 꺾쇠 없이 보내 썸네일을 허용합니다.
실제 표시는 Discord 설정·봇의 링크 임베드 권한·유튜브 응답에 따릅니다. 기존 글은 설명 재제출/내 지난 방송 타임라인 보기로 갱신합니다.
기존 메시지를 고쳐 쓰며, 내용 길이에 따라 필요한 페이지만 추가·삭제합니다. 공유 마킹이 들어간
다른 방송자도 함께 갱신합니다. 실패해도 설명·성공한 메시지 ID는 저장하며, 재제출하면 복구합니다.
이전 날짜·링크 전용 게시물도 설명 수정/재종료 시 타임라인이 붙습니다.
클립 링크를 별도 채팅으로 자동 게시하지는 않습니다. 녹화방의 방송 기록 마지막 페이지에
**🎥 클립 추출** 버튼을 붙입니다. 누른 사람만 마킹 선택 화면을 보며, 거기서 구간을 지정해 추출합니다.
다시 열면 최신 ✅와 클립 보기 링크가 나타납니다. 녹화방 타임라인 원문은 쪽 넘기기에 영향을 받지 않습니다.
방송 종료 때 선택 목록은 펼치지 않으며, 녹화방 미연결 시 요약판의 같은 버튼을 이용합니다.
기존 게시물은 설명 재제출 또는 `/방송`의 내 지난 방송 타임라인 보기로 버튼까지 갱신합니다.

### 3.4 스샷 포럼 — 지금 되는 것 + 조금 더

`/채널설정` 에 **스샷 포럼** 을 지정하면 2.6 의 이유로 **바로** 게임별 폴더 정리가 됩니다.
갤러리 링크 자동 게시나 스샷 포스트 자동 생성은 하지 않습니다.

## 4. 불변조건 (구현할 때 지킬 것)

### 4.1 스팀이 없어도 돌아가야 합니다

- 검색이 실패하면 **자동완성이 빈 목록**을 줍니다. 오류를 띄우지 않습니다.
  자동완성에서 오류를 내면 디스코드가 "응답하지 않았어요" 를 띄웁니다.
- 저장된 게임 정보는 원격 조회 없이 사용할 수 있습니다. 처음 고른 앱의 상세 조회가 실패하면 재선택/직접 입력을 안내합니다.
- 앱 번호를 이름으로 바꾸지 못하면 **`steam:1966720` 을 게임 이름으로 저장하면 안 됩니다.**
  그러면 포스트 제목이 숫자가 됩니다. 조회 실패 시 사람에게 다시 물어야 합니다.

### 4.2 ★ 포스트는 **이름으로 찾지 말고 id 로 찾습니다**

```
data/forum-posts.json
{
  "<서버ID>": {
    "rec:steam:1966720": "<스레드ID>",     ← 녹화 포럼 · 스팀 게임
    "rec:name:모여봐요 동물의 숲": "<스레드ID>",  ← 녹화 포럼 · 직접 입력
    "shot:steam:1966720": "<스레드ID>"      ← 스샷 포럼
  }
}
```

이름으로 찾으면 **게임 이름이 조금만 달라도 포스트가 하나 더 생깁니다.**
`Lethal Company` / `lethal company` / `레탈 컴퍼니` 가 각각 포스트를 만듭니다.
스팀 앱 번호가 있으면 이름이 흔들려도 같은 게임으로 알아봅니다.

### 4.3 ★ 기존 포스트 짝짓기는 **손으로** 합니다 (자동 짝짓기 금지)

소유자는 **이미 몇 달치 포스트를 손으로 만들어뒀습니다.** 봇이 그걸 무시하고
새 포스트를 만들면, 기존 기록과 새 기록이 갈라져 **지금보다 나빠집니다.**

확정 사항 (소유자 답):

> "녹화 50개, 스샷 17개 게임들이야. 이정도면 방법만 있다면 손으로 옮길만해.
> 스레드명도 게임명을 정확하게 적은게 아니라 별칭으로 적은것도 많아서
> 자동으로 옮기지 않고 수동으로 옮기는게 나아."

→ **자동 짝짓기를 만들지 않습니다.** 제목이 별칭이라 스팀 검색으로 맞출 수 없고,
잘못 맞추면 라이브 링크가 **다른 게임 포스트로** 들어갑니다. 그건 조용히 틀리는 종류의
오류이고, 67개를 사람이 검수하는 것보다 나쁩니다.

#### 어떻게 손으로 하는가 — **그 포스트 안에서 한 번**

목록을 만들어 짝지어주는 화면은 만들지 않습니다. **50개는 드롭다운(25개 상한)을 넘고**,
페이지를 넘기며 짝짓는 화면은 만드는 쪽도 쓰는 쪽도 고생입니다.

대신 **그 포스트에 들어가서 한 번 실행**하면 끝나게 합니다.

```
(녹화 포럼의 「발하임」 포스트 안에서)
/게임 검색:Valheim        ← 자동완성으로 Steam 게임을 고름
→ ✅ 이 포스트를 Valheim (892970) 에 연결했습니다.
```

- **포스트 안에서 실행하므로 어느 포스트인지 물어볼 필요가 없습니다.**
  (`/채널설정` 이 채널을 비우면 지금 채널로 지정하는 것과 같은 방식 — 3.8-1)
- 제목이 별칭이어도 상관없습니다. **제목을 안 보고 사람이 고른 게임에 붙입니다.**
- 녹화 50개 + 스샷 17개 = **67번.** 한 번에 몰아서 안 해도 됩니다 —
  안 붙인 게임의 기록은 종료 시 보류되며, 기존 녹화 포스트를 연결하면 자동 게시합니다.
- 이미 붙은 포스트에 다시 실행하면 **갈아끼웁니다** (잘못 붙였을 때).

⚠️ **봇은 새 포스트를 만들거나 제목으로 게임을 추측하지 않습니다.** 스레드 관리자가
게임을 확정한 뒤에만 포스트 제목을 별칭으로 학습합니다. 이미 연결한 포스트는 재연결하면 학습됩니다.

### 4.4 ⚠️ 지난 포스트는 **보관됨(archived)** 상태입니다

몇 주 전 게임의 포스트는 디스코드가 자동으로 보관합니다.

- `channel.threads.cache`에 없을 수 있어 저장된 포스트 ID로 `client.channels.fetch`합니다.
- 보관된 포스트에 글을 쓰면 **자동으로 보관이 풀립니다.** (권한이 있으면)
- 그래서 4.2 의 id 저장이 더 중요합니다 — 매번 보관 목록을 훑는 것은 비쌉니다.

### 4.5 포럼 태그는 **사람이 만든 것만** 씁니다

`availableTags` 는 읽을 수 있지만, 태그를 **추가하려면 채널 설정을 바꿔야** 합니다.
봇이 마음대로 늘리면 태그 목록이 지저분해집니다 (상한도 20개입니다).

→ 현재 태그 자동 부착은 후속 기능입니다. 지금 구현은 포스트 ID 연결이며 태그를 생성·수정하지 않습니다.

### 4.6 권한 검사에 포럼용을 더합니다

`channel-commands.js` 의 `permissionWarnings` 에 추가해야 합니다.

| 권한 | 없으면 |
|---|---|
| `채널 보기` | 아무것도 안 됩니다 |
| `스레드에서 메시지 보내기` | 포스트에 링크를 못 올립니다 |
| `메시지 기록 보기` | 기존 게시물을 가져와 수정하지 못합니다 |
| `스레드 관리` | 보관된 포스트를 못 풀 수 있습니다 |

지정하는 순간 없는 것만 한국어 이름으로 알려줍니다 (3.8-1 과 같은 방식).

### 4.7 `kind: 'forum'` 을 새로 만듭니다

`kind: 'text'` 를 느슨하게 풀면 **읽어주기 채널에 포럼을 고를 수 있게 되고**,
그건 동작하지 않습니다. 종류를 나눠야 합니다.

```js
const FORUM_TYPES = [ChannelType.GuildForum, ChannelType.GuildMedia];
if (spec.kind === 'forum' && !FORUM_TYPES.includes(channel.type)) {
  return '**포럼 채널**을 골라주세요. (게시물을 모으는 채널입니다)';
}
```

이미지 저장은 별도로 지정된 스샷 포럼 ID를 확인합니다 (2.6). 일반 텍스트 종류 검사는 바꾸지 않습니다.

### 4.8 이 저장소의 일반 규칙

- 새 설정은 `settings.js` 의 `KEYS` 에만 넣으면 `/채널설정` 선택지가 따라옵니다.
- **`.env.example` 에 반드시 추가하세요.** `verify.mjs` 가 "코드가 읽는 설정이
  example 에 다 있는가" 를 검사하고, 없으면 그 항목만 환경에 따라 검사가 흔들립니다.
- 자동완성은 `commandMap` 의 `autocomplete` 로 연결됩니다 (이미 배선돼 있음).
- 화면 만드는 함수는 **export** 해서 `verify.mjs` 의 화면 조립 검사에 넣으세요 (규칙 7-1).

## 5. 구현 상태

### Phase A — 게임 검색 ✅

포럼과 무관하게 **그 자체로 쓸모**가 있습니다. 게임 이름이 정확해집니다.

1. `src/game/steam.js` — 검색·정보 조회 + 캐시. 실패해도 죽지 않게.
2. `stream.game` · `stream.appid` 추가 (1절 — **맨 앞에 해야 합니다**)
3. `/방송` 의 `게임명` 자동완성
4. `/방송 게임명:<게임>` — 방송 중 자기 게임 바꾸기
5. 요약판·제어판 제목이 **사람별 게임**을 쓰게
6. 포럼 제목을 길드별 한글 별칭으로 저장하고 `/게임`·`/방송` 자동완성에서 로컬 우선 검색

### Phase B — 스샷 포럼 ✅

1. `kind: 'forum'` + 포럼 전용 채널 선택 타입 추가 (4.7)
2. 이미지 채널이 포럼을 받게
3. `permissionWarnings` 에 포럼 권한 (4.6)

**여기까지만 해도 스샷 정리가 자동이 됩니다** (2.6 — 이미 되는 것을 풀어주는 것).

### Phase C — 녹화 포럼 ✅

1. `/채널설정` 에 **녹화 포럼** · **스샷 포럼**
2. `data/forum-posts.json` — id 로 짝짓기 (4.2)
3. **`/게임 검색:<게임>`** — 그 포스트 안에서 한 번 실행해 손으로 붙이기 (4.3)
   → 이게 3번인 이유: 4·5번보다 **먼저** 있어야 기존 50개를 붙일 수 있습니다.
      안 그러면 봇이 중복 포스트를 만들기 시작합니다.
4. 짝지어진 포스트 찾기 (보관된 것 포함 — 4.4)
5. 방송 종료 시 라이브 링크·방송자·시작 날짜·타임라인 게시 및 설명 수정 동기화
6. 연결 전 기록은 보류했다가 포스트 연결 시 올리기

### Phase D — 나중에 (선택)

- 포럼 태그 붙이기 (사람이 만든 것만 — 4.5)
- `협동` 카테고리로 "다 같이 하는 게임" 을 알아보고, 마킹을 기본으로 모두에게
- 게임별 통계 (몇 번 했는지, 마킹이 몇 개인지)

## 6. 남은 정책

지금 구현을 막는 정책 질문은 없습니다. **협동게임 여부에 따라 세션을 자동 분리하거나
마킹을 자동 공유하는 규칙**은 오판했을 때 기록이 섞이므로 별도 상세 기획 뒤에 구현합니다.

### 구현하면서 확정된 정책

- **봇은 새 포스트를 만들지 않습니다.** 기존 포스트에 사람이 `/게임 검색:<게임>` 으로 연결할 때까지 보류합니다.
- `/게임` 하나가 두 역할을 합니다. 포럼 포스트 안에서는 연결, 다른 채널에서는 스샷·녹화 포스트 검색입니다.
- 방송 게임은 `session`이 아니라 **방송자별 `stream`**에 저장합니다.
- 방송 종료 시 녹화 포스트에 **방송자·시작 날짜·라이브 링크·타임라인**을 올리고, 설명 수정 시 기존 게시물을 함께 갱신합니다.
- 스레드 관리자는 `/게임 검색:<게임> 별칭:<한글명>`으로 수동 별칭도 추가할 수 있습니다.
- 연결 전 종료된 기록은 지우지 않고, 녹화 포스트를 연결하는 순간 자동으로 전송합니다.
- 연결을 바꿀 수 있는 사람은 Discord의 **스레드 관리** 권한 보유자로 제한합니다.
- 버튼은 검색창을 띄울 수 없어 **마지막 게임**을 재사용합니다. 게임이 바뀌면 `/방송` 자동완성에서 다시 고릅니다.
- Steam 게임을 포스트에 연결하면 **포스트 제목을 한글 별칭으로 자동 저장**합니다. 이후 띄어쓰기·이모지와 무관하게 일부 이름으로 검색할 수 있습니다.
- 제미나이 번역은 호출 지연·한도·오연결 위험 때문에 사용하지 않습니다.
- 협동게임 여부를 이용한 세션/마킹 자동 공유는 오판 가능성이 있어 후속 상세 기획으로 남깁니다.

**해결된 것** (소유자 답으로 확정):

- 포스트 개수 → 녹화 **50개** · 스샷 **17개**
- 짝짓기 방식 → **수동.** 제목이 별칭이라 자동 짝짓기는 안 만듭니다 (4.3)

## 7. 확인하지 않은 것 (구현할 때 실측할 것)

- **보관된 포스트에 글을 쓰면 정말 보관이 풀리는지.** 권한에 따라 다를 수 있습니다.
- **포스트 안에서 슬래시 명령어가 되는지.** 4.3 이 여기 걸려 있습니다.
  스레드에서도 명령어는 되는 것으로 알지만 **포럼 포스트에서 확인해봐야** 합니다.
  안 되면 짝짓기를 **메시지 우클릭 → 앱** 으로 해야 합니다 (`/일정에 등록` 과 같은 방식).
- **스팀 `appdetails` 의 요청 한도.** 자주 부르면 막힐 수 있어서 캐시가 필수인데,
  정확한 한도는 문서화돼 있지 않습니다. 넉넉히 캐시하고, 막히면 이름만 씁니다.
- **자동완성 응답이 3초 안에 들어오는지** (소유자 서버에서). 집 PC 는 빠르지만
  1코어 서버 + 해외 요청이라 재봐야 합니다. 느리면 캐시를 더 공격적으로 씁니다.

### 2026-09-04 개인 타임라인 표시

방송 종료 요약은 종료 버튼을 누른 본인에게만 나만 보기로 표시합니다. 다른 참여자는 `/방송` → **내 지난 방송 타임라인 보기**에서 확인합니다. 개인 재조회는 본인 녹화 글만 갱신합니다. 녹화방 공유·공유 마킹 설명 동기화는 유지합니다. 개인 요약은 다시 열어 최신 내용을 확인하며, 과거 공개 요약은 자동 삭제·전환하지 않습니다. 자체 검사 1,243개 통과, 실제 Discord 표시는 운영 확인 필요.
